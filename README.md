# R-Match — by Roger&Michin Studio

Android-приложение для футбольной статистики и вероятностного анализа матчей.
Все данные приходят **только** из официального API [API-Football.com (API-Sports)](https://www.api-football.com/).
В приложении нет демо-данных, заглушек и «придуманных» матчей: если поставщик не отдал данные —
на экране показывается честное сообщение об отсутствии данных.

---

## Что умеет приложение

| Вкладка | Содержимое |
|---|---|
| **Матчи** | ближайшие, live и завершённые матчи, фильтры по дате (вчера/сегодня/завтра/live), поиск по командам, лигам и странам, группировка по датам |
| **Лиги** | список лиг по странам, детальная карточка лиги: турнирная таблица и календарь |
| **Аналитика** | модуль **R-Match Analyst** — детерминированная статистическая модель (Пуассон) |
| **Эфир** | только сообщение о том, что поддерживаются исключительно будущие официальные ссылки правообладателей. Пиратских трансляций нет и не будет |
| **Настройки** | статус ключа, квота из заголовков ответа, проверка соединения, смена и удаление ключа, очистка кэша, предупреждение о продакшн-прокси |

Карточка матча состоит из вкладок: **Обзор**, **Аналитика**, **Составы**, **Статистика**, **Коэффициенты**.
Также есть карточки команды (форма, последние и ближайшие матчи, состав, тренеры) и игрока
(только те поля, которые вернул поставщик).

## Ключ API-Football

1. Зарегистрируйтесь на <https://www.api-football.com/> (или через RapidAPI-аккаунт API-Sports).
2. В личном кабинете скопируйте значение ключа (заголовок `x-apisports-key`).
3. При первом запуске R-Match попросит ввести ключ. Ключ проверяется запросом `/status`
   и сохраняется **только на устройстве** в `EncryptedSharedPreferences` (AES-256, `ApiKeyStore`).

**Ключ никогда не попадает** в исходный код, `BuildConfig`, Room, DataStore, логи, README, CI
и репозиторий. Проект собирается в CI без какого-либо ключа: без ключа приложение просто
открывает экран ввода ключа.

### Смена и удаление ключа

* **Настройки → Смена ключа** — введите новый ключ, он проверяется у поставщика, после успеха кэш очищается.
* **Настройки → Удалить ключ** — подтверждение, затем ключ стирается из защищённого хранилища,
  кэш очищается, приложение возвращается к экрану онбординга.

### Бесплатный тариф и лимиты

Бесплатный план API-Football даёт ограниченное число запросов в сутки (порядка 100).
Поэтому R-Match:

* показывает остаток квоты из заголовков `x-ratelimit-requests-remaining` / `x-ratelimit-requests-limit`
  и данные `/status` (тариф, запросы за сутки, дата окончания подписки);
* кэширует ответы в Room и грузит данные вкладок карточки матча только при их открытии;
* при сетевой ошибке показывает устаревший кэш с явной пометкой «из кэша» и временем загрузки;
* при HTTP 429 выводит «Лимит API исчерпан».

### TTL кэша

| Данные | TTL |
|---|---|
| Live-матчи | 30 секунд |
| Ближайшие матчи и календарь | 5 минут |
| Коэффициенты | 10 минут |
| Турнирные таблицы | 1 час |
| Статические данные (команды, игроки, лиги, страны) | 24 часа |

## Только реальные данные

* Используются исключительно документированные эндпоинты API-Football:
  `/countries`, `/leagues`, `/fixtures`, `/fixtures/events`, `/fixtures/statistics`,
  `/fixtures/lineups`, `/standings`, `/teams`, `/teams/statistics`, `/players`,
  `/players/squads`, `/coachs`, `/injuries`, `/odds`, `/status`.
* **Нет парсинга сторонних сайтов**, обхода robots.txt, CAPTCHA, платного доступа,
  авторизации, лимитов или геоблокировок.
* **Нет пиратских трансляций.** Вкладка «Эфир» сообщает, что поддерживаются только будущие
  официальные ссылки правообладателей.
* Если поставщик не дал данные, показываются честные сообщения:
  «Нет верифицированных данных», «Составы пока не опубликованы поставщиком»,
  «Недостаточно данных для расчёта», «Коэффициенты недоступны», «Лимит API исчерпан».
* На каждом экране с данными есть подпись источника: «Данные: API-Football.com • Roger&Michin Studio»
  и время последнего обновления.

## Методика R-Match Analyst

Модуль полностью детерминированный: **никакого ИИ, никаких случайных чисел, никаких внешних
сервисов прогнозов**. Все формулы описаны в комментариях
`core/domain/analyst/MatchAnalyst.kt` и `PoissonCalculator.kt`.

1. Используются только завершённые матчи, отданные поставщиком.
   Требуется минимум **5** завершённых матчей у **каждой** команды (в расчёт берутся до 10 последних).
   Если данных меньше — расчёт не выполняется: «Недостаточно данных для расчёта».
2. Вес свежести матча: `w_i = 0.5 ^ (i / 5)`, где `i = 0` — самый свежий матч.
3. Базовая результативность считается по самой выборке (никаких «средних по лиге» констант):
   `baseline = Σ w_i * (забито_i + пропущено_i) / 2 / Σ w_i` по матчам обеих команд.
4. Индексы: `атака_T = взвешенные забитые_T / baseline`, `оборона_T = взвешенные пропущенные_T / baseline`.
5. Фактор поля измеряется по выборке (доля результативности дома/в гостях), ограничен диапазоном `[0.80; 1.25]`.
6. Ожидаемые голы:
   `λ_дом = baseline × атака_дом × оборона_гости × фактор_дома`,
   `λ_гости = baseline × атака_гости × оборона_дом × фактор_выезда`.
7. Подтверждённые травмы: −3 % к λ за игрока, не более −15 %.
   Положение в таблице (очки за матч) корректирует λ не более чем на ±8 %.
8. Матрица счёта строится как произведение двух пуассоновских распределений,
   обрезается на 10 голах и **нормируется к 1.0**.
9. Из матрицы считаются: 1X2 (сумма ровно 100 %), тоталы 1.5/2.5/3.5, обе забьют (BTTS),
   форы 0 / ±0.5 / ±1.5, ожидаемые голы и ожидаемый тотал.
10. В отчёте показываются: сколько матчей использовано, какие факторы учтены,
    оценка качества данных (0–100), время расчёта и список рисков модели.

### Коэффициенты

Коэффициенты берутся из `/odds` API-Football и показываются нейтрально:
букмекер, рынок, десятичный коэффициент, поставщик, время обновления и признак свежести.
Дополнительно считаются подразумеваемая вероятность `1 / коэффициент`,
маржа (overround) `Σ вероятностей − 1` и рыночные вероятности без маржи.
Отклонение «модель − рынок» показывается **только** если линия полная и свежая (не старше часа).

## Технологии

Kotlin • Jetpack Compose • Material 3 • Navigation Compose • MVVM • Coroutines/Flow •
Retrofit + OkHttp • Kotlinx Serialization • Room (кэш) • DataStore • AndroidX Security
(EncryptedSharedPreferences) • Coil.

Архитектура: `core/{data,domain,network,db,datastore,security,di,util}` + `feature/*` + `ui/*`.
Слой сети возвращает DTO, мапперы превращают их в доменные модели — **DTO никогда не попадают в UI**.

Сборка: JDK 17, `minSdk 26`, `compileSdk 35`, `targetSdk 35`.

## Локальная сборка

```bash
git clone https://github.com/andreww99982-code/football.git
cd football
chmod +x gradlew

./gradlew test            # юнит-тесты (модель, вероятности, коэффициенты, мапперы, хранилище ключа)
./gradlew :app:assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.
Ключ API для сборки и тестов **не нужен**: он вводится в самом приложении.

CI (`.github/workflows/android.yml`) выполняет `./gradlew test`, `./gradlew :app:assembleDebug`
и публикует артефакт `R-Match-debug-apk`.

## Предупреждение о продакшн-режиме

Хранение ключа поставщика на устройстве допустимо только для личного использования.
Для публичного релиза вынесите ключ на собственный backend-прокси:

* приложение обращается к вашему серверу без ключа поставщика;
* сервер добавляет `x-apisports-key`, кэширует ответы, контролирует лимиты и аудит;
* ключ хранится в секретах сервера и не покидает инфраструктуру.
